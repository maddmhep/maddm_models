# MadDM models

A collection of UFO models for dark-matter phenomenology with
[MadDM](https://github.com/maddmhep/maddm) (MadGraph5_aMC@NLO plugin).
For each model the repository keeps the UFO used by MadDM together with
the FeynRules source it was generated from, so that the model can be
inspected, modified and re-exported.

## Repository structure

Every model lives in its own top-level folder named after the model:

```
SM.fr                     # FeynRules SM file (v1.4.6), shared by all models
<ModelName>/
├── <ModelName>/          # UFO model (the folder MG5_aMC / MadDM imports)
│   ├── __init__.py
│   ├── particles.py, parameters.py, vertices.py, couplings.py, ...
│   └── <ModelName>.log   # FeynRules export log
├── <model>.fr            # FeynRules model file (BSM fields, parameters, Lagrangian)
└── <model>.nb            # Mathematica notebook that loads FeynRules and exports the UFO
```

For example, `eDMsimp_s_spin0/` contains the UFO `eDMsimp_s_spin0/eDMsimp_s_spin0/`,
the model file `edm_s_spin0.fr` and the notebook `edm_s_spin0.nb`.

The `SM.fr` at the root of the repository is shared by all the models: each
notebook moves to its own folder with `SetDirectory[NotebookDirectory[]]` and
loads `LoadModel["../SM.fr", "<model>.fr"]`, then writes the UFO next to the
notebook. The only path to adapt is `$FeynRulesPath` in the first cell.

Files generated by MG5_aMC when it imports a model (`__pycache__/`,
`py3_model*.pkl`) and zipped copies of the UFO are not tracked (see `.gitignore`).

### `eDMsimp_s_spin0`
Simplified model for DM–electron scattering through an s-channel real scalar
mediator `Y0`. The mediator couples to the DM through `gSXr`, `gSXc`, `gSXd`,
`gSXm` and to the electron through `gSe` (block `DMINPUTS`). Set the couplings
of the DM species you are not studying to zero. Based on
H. Alhazmi et al., [arXiv:2006.16252](https://arxiv.org/abs/2006.16252).
Author: G. M. Lucchetti.

### `eDMsimp_s_spin1`
Same as above with a spin-1 mediator `Y1`: vector couplings `gVXc`, `gVXd`,
`gVe` and axial couplings `gAXd`, `gAXm`, `gAe` (block `DMINPUTS`).
Author: G. M. Lucchetti.

### `DMsimp_s_spin0_MD`
The spin-0 s-channel model of the
[DMsimp](http://feynrules.irmp.ucl.ac.be/wiki/DMsimp) family
(A. Martini, K. Mawatari, J. Wang, C. Zhang, v1.1), in the version prepared
for MadDM: the dark-sector fields carry the `~` prefix (`~xr`, `~xc`, `~xd`).
Couplings to DM `gSXr`, `gSXc`, `gSXd` (scalar) and `gPXd` (pseudoscalar)
and to quarks `gS{u,d}ii`, `gP{u,d}ii` (in units of the quark Yukawa
couplings), all in block `DMINPUTS`. The block also contains `Lambda`, `gSg`,
`gPg` for the effective `Y0 G G` operators: they are defined in the `.fr`
(`L0SMg`) but not exported to the UFO, so they have no effect.

### `DMsimp_s_spin1_MD`
The spin-1 s-channel model of the same DMsimp family
(A. Martini, K. Mawatari, J. Wang, C. Zhang, B. Zaldivar, v2.0), also in the
MadDM version with `~`-prefixed dark-sector fields (`~xr`, `~xc`, `~xd`). Couplings `gVXc`, `gVXd`, `gAXd` to DM and `gV{u,d,l}ii`,
`gA{u,d,l}ii`, `gnuii` to the SM fermions, all in block `DMINPUTS`.
The new couplings carry the interaction order `QED`, except `gnu33` (`DMV`).

### `ScalarHiggsPortal_MDM_UFO_NLO`
Real scalar singlet DM `~SDM` coupled to the SM through the Higgs portal,
with parameters `mSDM`, `lambdahs` (portal coupling) and `lambdas` (self
coupling) in block `SCOUPLINGS`. The UFO includes the NLO counterterms
(`CT_vertices.py`, `CT_couplings.py`) for one-loop computations.
Author: M. Di Mauro.

## Usage

Copy or symlink the UFO folder (the inner `<ModelName>/<ModelName>`) into the
`models/` directory of MG5_aMC, then from MadDM:

```
import model eDMsimp_s_spin0
define darkmatter Xd
generate direct
...
```

Alternatively, import the model with its full path:
`import model /path/to/maddm_models/eDMsimp_s_spin0/eDMsimp_s_spin0`.

## Adding or updating a model

1. Create a top-level folder `<ModelName>/` following the structure above.
2. Put the UFO in `<ModelName>/<ModelName>/`, without `__pycache__/` or
   `py3_model.pkl`.
3. Add the FeynRules `.fr` file(s) and the Mathematica notebook that exports
   the UFO, loading the shared `../SM.fr` (add a model-specific SM file only if
   the model needs a modified SM).
4. Add a row to the table above and a short description: mediator, DM
   candidates, names and LHA blocks of the new parameters, authors and
   reference.

For the models marked ⏳ the FeynRules source and notebook are still missing;
contributions from the model authors are welcome.
